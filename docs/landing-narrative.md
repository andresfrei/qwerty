# Guided public landing

The public `/` page is synchronous and does not read cookies, session or business data to choose its copy. The header always exposes a native `Ingresar` link to `/ingresar`; that separate private route resolves fresh identity. See [entry contract](landing-entry.md).

The landing keeps Qwerty's cream, ink and lime tokens and Manrope from the unchanged shared layout. A landing-only stylesheet scopes every selector beneath `.qwerty-landing`; it does not alter the global reset, Owner or Auth styles.

## One illustrative turn

On wide, sufficiently tall viewports, one example panel remains beside the story and updates when chapters enter the reading area. Its chapter links are ordinary anchors. The client observer is progressive enhancement, uses height-based pixel margins, rebuilds on resize, disconnects on unmount and performs no network requests.

At narrower widths the persistent panel is hidden and each chapter contains its own inline illustration. Short desktop windows do not pin the panel. No animation or smooth scrolling is required; reduced-motion preferences disable motion styles. All chapters, native links and FAQ details are rendered in HTML and remain usable without JavaScript or IntersectionObserver.

The same example order is used throughout. Preparation and delivery never imply payment confirmation; the transfer remains pending and a courier run can still await settlement. Order examples, states and amounts are labelled conceptual. The landing does not claim that all illustrated operations are implemented, promise provider-fee-free service, publish a price, fabricate customer metrics or offer a marketplace/courier fleet.

## Boundaries

The approved reference supplies guided storytelling and composition, not its terminal styling, colors or content. Owner/Categories work is explicitly paused. No dependencies, live business records, auth recovery protocol, services or delivery settings were changed for this presentation.

## Verification

Node tests cover stable native entry, complete readable chapters, separate financial states and synchronous session-independent rendering. Typecheck and scoped lint accompany those checks. Browser verification must separately establish hydration, geometry, observer-driven chapter changes, native navigation, no-JavaScript behavior and reduced-motion behavior. Synthetic browser sessions do not certify live provider refresh, authenticated account acceptance or production Next routing/build behavior.

The first authorized browser run passed 11 preliminary desktop checks, including hydration and layout, then timed out waiting for a scroll-selected chapter. No complete scenario or mobile/reduced-motion/no-JS acceptance was obtained. A source review separately found and corrected width-resolved percentage observer margins; its deterministic regression and targeted independent recheck passed four tests, with typecheck/lint passing. This does not prove the captured timeout's exact cause or corrected browser success. After fresh authorization, the corrected run passed **72 checks across four cases**: desktop 1440px (including 800px/640px height changes), mobile 390px, reduced motion and JavaScript disabled. It verified hydration, chapter changes, native FAQ, non-obstructive mobile examples and native entry with simulated valid/absent identity. No console/page errors or unexpected requests occurred; the browser closed. The first failed run is retained. The final focused Node suite passed 51 tests; typecheck/scoped lint and the directed independent checks passed. These counts overlap and are not a total of unique scenarios.
